# Local live radar diagnostic

Custom local graph for official AWR2944P TDM output, not the TI GUI or the existing project dashboard. Reads actual processed points only; no synthetic/replay fallback, raw ADC or clinical/fatigue scores.

A separate car-style demo is served at `http://127.0.0.1:8766/drive/`, sourced from `sandbox/radar-car-demo/`. This Room map HTML remains unchanged. Both pages share the same collector/profile and Start/Stop controls; Close viewer here ends the service for both. The Drive page's illustrative vehicle/reflection groups are display symbols, not detected cars/people or road/lane estimates.

The interactive 3D view uses each measured point's actual x/y/z in meters. Drag with a mouse or one finger to orbit; scroll, pinch with two fingers or use Zoom +/− to zoom. Top and Front select view presets; Reset view restores perspective. With the plot focused, arrow keys orbit, +/− zoom and Home resets. Camera controls never send radar commands. The z=0 grid is the plane through the radar, not a measured floor. Height z is relative to the radar; this is a sparse reflection cloud, not a camera image, body surface or skeleton.

Distance colors use the existing 3D `range`: red/orange nearby, green/cyan intermediate, blue at or beyond the selected display-range distance. The legend updates with Display range and is independent of camera angle/zoom. Display range sets a volume x/z within ±range and forward y from 0 through range; the visible/total counter also accounts for camera clipping. Soft halos are illustrative, not measured surfaces, temperature, signal power or extra detections. Unmeasured areas stay blank; stopped data is dimmed and labeled. Receiver and displayed unique-frame rates are measured separately. Camera controls do not alter measurement settings.

Use the existing task-isolated Python with pyserial. Run `server.py --profile <absolute path to copied official AWR2944P TDM cfg>`, then open `http://127.0.0.1:8766/` and click Start. CLI COM5=115200, data COM6=3125000. Firmware must report AWR2X44P/TDM/SDK 04.07.02.01. Keep other serial tools closed.

Start sends runtime configuration only, not flash writes. Stop paces the CLI command, retries up to three times and requires acknowledgement; an unconfirmed stop is shown as an error. Serial ports are released. Close viewer stops acquisition and server. A 15-second viewer-heartbeat loss or 15-minute session limit stops acquisition automatically; Start resumes a new session. The graph is marked Live only while fresh real packets arrive; stopped/disconnected data is explicitly labeled not live.

Run parser tests with `test_packets.py --capture <absolute radar-smoke-capture.dat path>`. Synthetic fixtures are test-only; the separate real-file check must accept all 151 packets already independently validated by TI's parser.

Server binds only to loopback with host/origin/token checks on controls; no external scripts, uploads, public hosting or network/firewall changes. Installed TI SDK, main frontend, Pi bridge and submitted documents remain untouched. Run PID, logs and verification are recorded in the CLAUDE report. No commit/push.

## Fixed-radar room map

The default Room map mode accumulates measured front-of-radar reflections in browser memory while the board stays fixed. Display range defaults to 10 m to show a broader area; this is a view/color scale, not a changed detection range. Live points remains available in the Display mode selector, and orbit/zoom/Top/Front/Reset work in both modes.

Squares represent 10-cm display cells observed in at least three distinct received frames within the 30-second observation window. Positions average the most recent three per-frame cell centroids; distance colors derive from these coordinates. Multiple detections in one frame count once per cell, and repeated cursor frames are ignored. Circles still show the latest actual measured frame. Ten-centimeter grouping is not a claim of physical/angular accuracy or a room mesh. Empty regions are unknown, not confirmed free space.

By default only returns with absolute radial velocity at most 0.15 m/s enter the environment layer. Include moving reflections changes that filter and clears the map. Low radial velocity is not proof an object is static: tangential motion and stationary people may enter, and moving people can leave temporary trails. No CFAR, antenna, RF profile, firmware, frame-rate target or server/security changes are made by this feature.

Pause map freezes accumulation and aging while the radar can remain live; the separate label says Paused / historical map. Resume advances the observation clock and removes expired samples before accumulating new frames. Stopped/stale/disconnected acquisition freezes the map as historical. Clear map removes cells but preserves cursor deduplication; a new acquisition session/reconnect clears accumulation. Clear after moving the board: no pose correction or SLAM is performed. Reload also resets the RAM-only map. There is no new dataset recording/export/upload.

At most 2000 candidate plus persistent cells are retained; least-recently-seen cells are evicted if needed. The map layer caches snapshots for up to 100 ms while live-frame rendering and the separate receiver-rate metric continue. Every incoming delivered real frame can contribute even if the live animation queue discards old display frames. Existing packet-gap counters remain visible; missing packets never create map observations. Map colors retain radar distance semantics, and historical tooltip ages are relative to the frozen snapshot.

Run `node test_room_map.js` with the existing bundled Node/runtime. Eleven focused checks cover persistence, duplicate suppression, measured coordinates/range, expiry, bounds/eviction, moving filtering, pause/resume, stale freezing, clear/session reset, invalid inputs, cursor-history accumulation and reconnect. Fixtures are unit-test-only and never served as real data. This is a sparse accumulated reflection view; room surfaces and full scene coverage have not been validated.

## Selected fast profile

Use `profiles/tdm-wide-points-40hz.cfg`: target 40 Hz, 736 samples at 13.349 Msps, full sweep 76.55 to 80.9698 GHz, sampled bandwidth 3.8595 GHz, nominal radial range separation 3.8839 cm and Doppler separation 0.1190 m/s. This is a tested derivative of TI's profile. It sends measured points, SNR/noise and health statistics; the unused range-profile TLV is disabled. Detection thresholds and antenna geometry are unchanged. No bias, phase or absolute-position calibration is claimed. `profiles/tdm-baseline-10hz.cfg` preserves the original waveform and output as rollback. Full-telemetry 20/30/40-Hz and wider-band comparison profiles are also retained.

The browser polls without overlapping requests, with an 8-ms delay after each response. Local HTTP/1.1 and TCP_NODELAY reduce transport overhead. A bounded server history/cursor and client queue retain real frames delivered in USB bursts. Animation displays at most one measured frame per browser animation tick, never interpolating positions or creating measurements. Queued frames older than 250 ms are discarded to keep the view current. Data age refers to the displayed packet's receive age; RF acquisition and USB delay are additional.

The SDK stats TLV's processing time belongs to the current frame; margin and UART time belong to the previous frame. Reserve subtracts UART time from margin. CPU-load zeros do not imply unlimited headroom. For AWR2x44P the legacy DIG0 temperature field is TX3 and DIG1 is reserved; the reserved field is excluded from the maximum. Valid reports reaching a conservative 85 C, or reserve below 5% for three frames, stop acquisition. Profiles must first pass bounded tests with at least 10% reserve. Results depend on scene and output density.

The SDK documents VCO2 sub-bands of 76-80.5 or 76.5-81 GHz, each 4.5 GHz. Full 5-GHz chip coverage must not be assumed for one chirp. Settling and ADC capture time further constrain sampled bandwidth. FFT padding or extra displayed decimals do not improve physical separation/accuracy.

`benchmark.py --profile <cfg> --seconds 12 --output <json>` runs an approved bounded 5-60-second test with timing, temperature, gap counters and verified stop. JSON contains sampled measured states and aggregate counters, not full raw ADC recordings. Close/stop the live viewer before using its ports. The 48-Hz candidate failed the 10%-reserve check. Although 45 Hz passed a bounded 60-second test, extended GUI operation later showed one sequence discontinuity, so 40 Hz is the final selected default; 45/48 Hz remain experimental. See the CLAUDE tuning report for limits, exact logs and the running process. No commit/push.
