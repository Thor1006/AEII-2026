## Why
The network can't be trained, or even checked against reality, without recordings where the radar frames
line up in time with ground truth: MyoWare sEMG (fatigue), MPU6050 IMU and video pose (compensation).
Nothing records data today.

## Approach
`recorder/record.py`: one command starts a session; each sensor runs on its own thread and writes its own file.
Every sample gets a host timestamp from one clock (`time.perf_counter_ns`).

1. **Session folder** `recorder/data/sessions/<date>_<time>_<subject>_<exercise>/` (git-ignored):
   `meta.json` (subject *code*, never a name; exercise; radar config copy; sensor list; software version; notes),
   plus one file per sensor and `markers.csv`.
2. **Radar** (works now): raw bytes to `radar.bin` + `radar_index.csv` (frame no., host time, offset, length),
   so frames can be re-parsed later with any new processing. Keeps the command port open and stops the radar
   at the end (this also tests stop-on-close).
3. **sEMG** (works now): MyoWare lines over Bluetooth (`/dev/cu.TrueRehab-MyoWare`) or USB → `emg.csv`.
   Proposed firmware change (you upload it): a "record" mode sending **RAW and ENV at 1 kHz** with the ESP32's
   own microsecond timestamps, in batches. Why: the current 50 lines/s of the envelope can show effort rising,
   but the classic fatigue sign (median-frequency drop) needs the raw signal at ≥1 kHz, and Bluetooth delivery
   jitters by tens of ms, so device timestamps are more accurate.
4. **IMU** (after you test the MPU6050): ax, ay, az, gx, gy, gz at 100–200 Hz with device timestamps → `imu.csv`.
   Same ESP32 if its I2C pins are reachable, otherwise its own board/port.
5. **Video pose** (second step): Continuity Camera through OpenCV, MediaPipe Pose (33 landmarks) → `pose.csv`.
   Raw video **off by default** (privacy); a flag turns it on.
6. **Markers:** keys during recording (space = rep start, t = "feels tired", c = "compensating", x = note) → `markers.csv`.
7. **Sync check:** start each session with 3 quick shoulder shrugs. They show in radar, sEMG, IMU and video, so the
   offsets between sensors can be measured and corrected afterwards.
8. **Live status line:** per-sensor rate and lost samples, so a broken sensor is obvious during the session.
9. **Reader:** `recorder/rec/session.py` loads a session back into numpy arrays on a common time axis.
