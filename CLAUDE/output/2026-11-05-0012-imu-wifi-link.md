# Report: IMU board streams over Wi-Fi; recorder reads it and keeps its timing exact

<!-- Filename: YYYY-MM-DD-HHMM-<slug>.md -->

**Date:** 2026-11-05 00:12 · **Result:** ✅ done · **Plan:** [plans/2026-11-04-imu-wireless.md](../plans/2026-11-04-imu-wireless.md)

## Goal
Let the IMU ESP32 send its data without a USB cable (the user chose Wi-Fi over Bluetooth), so it can sit on a moving arm, and record it with `recorder/`.

## What changed
- `sandbox/imu-mpu6050-oled/imu_mpu6050_oled/imu_mpu6050_oled.ino` (fw 2.1): optional `WIFI_LINK 1`.
  - The board joins Wi-Fi as `truerehab-imu.local` and serves one TCP client on port 3333.
  - Every printed line still goes to USB. Whole lines also go into a 32 KB buffer that a core-0 task sends, so
    200 Hz sampling never waits for the network.
  - On connect the board sends its header and status at once, and keys work from the client.
  - The OLED and status line show the Wi-Fi state, IP, RSSI, `link_clients`, `link_dropped` and
    `link_send_fails`. With `WIFI_LINK 0` the output is unchanged.
- `wifi_secrets.example.h` (new) and `.gitignore` (`wifi_secrets.h`): the Wi-Fi password stays on this Mac. Without
  the file, the build stops with instructions.
- `recorder/rec/sources.py`: `tcp://host:port` sources over a plain socket.
  - The name is looked up over IPv4 first: for `.local`, macOS otherwise waits 5 s for IPv6 (5 ms vs 5005 ms).
  - When the link closes or is quiet for 6 s, the recorder reconnects once a second and writes
    `# recorder: link lost/back` rows. Half lines are discarded.
  - An unreachable board fails before recording starts.
- `recorder/rec/session.py`: `align_device_time` now fits clock drift through the least-delayed sample of each
  2-s window (the lower edge), not through all samples.
- `recorder/record.py`: `--imu` help text, a clean message for unreachable ports, and an elapsed-time display fix
  ("01:60.0" → "02:00.0").
- `recorder/tests/test_recorder.py`: new tests for a fake Wi-Fi IMU (one close and one silent drop), an
  unreachable board, `tcp://` parsing, and delay bursts (on that scenario the old fit spreads 26 ms, the new one
  0.00 ms). 13 tests in total.
- READMEs (IMU, recorder), plans and CONTEXT updated.
- Earlier in this loop (Nov 4):
  - Video pose was verified on the MacBook webcam (camera 0, checked by eye).
  - `firmware/myoware_record` compiles (USE_IMU 0 and 1, 83 % flash) but has not been run.

## Verified by
- **Builds:** LIVE and RECORD each compile with `WIFI_LINK` 0 and 1, with no warnings from the sketch (75 % flash
  with Wi-Fi). A missing `wifi_secrets.h` stops the build with a clear `#error`.
- **Upload:** the user OK'd it; the IMU ESP32 (`/dev/cu.usbserial-0001`) was flashed and the hash verified. It
  joined home Wi-Fi at RSSI −31 to −46 dBm.
- **2-min session** `recorder/data/sessions/2026-11-05_000433_TEST_wifi_check`. Wi-Fi was recorded as `imu`, and
  the board's USB output as the reference in the `emg` slot.
  - Board: 200.0 Hz, `skipped=0`, `i2c_err=0`, `link_dropped=0`.
  - All 23,805 samples present in both copies are byte-identical.
  - Forced takeover at 40 s: the recorder reconnected after 1.0 s (`link_drops=1`), leaving one 1.0-s gap in the
    Wi-Fi copy only.
  - Delivery: Wi-Fi arrived a median 15 ms after USB. 13 % of samples were > 30 ms late and 2 % > 100 ms. Two
    ~1-s pauses were bridged by the board's buffer, with nothing lost.
- **Alignment:** with the old fit, Wi-Fi-aligned times wandered 37 ms against the USB-aligned ones. With the new
  fit they are a constant 4.10 ms apart (spread < 0.01 ms).
- **Final build, 20 s** (`2026-11-05_001132_TEST_wifi_final`): 200.05 Hz, no gaps, common samples identical,
  4.0 ms apart (p1–p99 3.6–4.4 ms).
- **Recorder tests:** 13/13 pass; the Wi-Fi tests ran 3 times.

## Issues / not done
- **Not tested:**
  - Wi-Fi switched off mid-recording (only a simulated silent link);
  - power-bank power;
  - a moving arm;
  - a phone hotspot or school network.
- **Wi-Fi pauses:** the ~1-s pauses come from the Mac or the router; which one is unknown. They no longer affect
  data or timing, but they would delay a live display.
- **Sensor check, Nov 4:**
  - The radar was not plugged in.
  - The MyoWare was on and in range, but macOS listed it "Not Connected" and its port gave 0 bytes in 15 s.
  - The MyoWare record sketch has never run.
- **Security:** anyone on the same network can read the IMU stream or send its keys.
- **Board state:** the IMU board is left running the Wi-Fi RECORD build (fw 2.1).
